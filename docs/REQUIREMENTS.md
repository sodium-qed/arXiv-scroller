# Requirements and acceptance coverage

The delivered browser format is a Tampermonkey userscript, as requested in the final instructions. Its checked-in installable is `dist/arxiv-discovery.user.js`. The userscript metadata declares execution scope and grants, and Tampermonkey owns the installation and update flow. This supersedes the earlier standalone Manifest V3 and Chrome Load Unpacked packaging requirements.

## Feature map

| Brief section | Delivered behavior and location |
| --- | --- |
| 1–2. Objective and source | The reader can leave the original announcement visible while using the added tools. The parser normalizes paired paper rows across all article lists and preserves source math, authors, links, submission sections and the displayed announcement date. [Ingestion](INGESTION.md) |
| 3. Mathematics taxonomy | All 32 mathematics categories participate in sampling using primary and secondary classification. The taxonomy normalizes supported equivalences, including math-ph and cs.IT. [Taxonomy and aliases](INGESTION.md) |
| 4. Daily selections | A complete dated pool, seeded random priorities and maximum matching produce distinct assignments and missing-category explanations. The daily panel supports regeneration, individual replacement, original restoration, history and category browsing. New, cross and replacement eligibility are explicit. [Daily sampling](RECOMMENDER.md) |
| 5. Paper interface | Source title, authors and classifications, date, expandable abstract, source links, rationale, follow controls, explicit responses, read status, bookmarks and an optional AI overview appear in paper cards. Shortcuts and reviewed-paper counts accompany the finite list. [Usage](../README.md) |
| 6–7. Learning and modes | A regularized local logistic classifier learns from inclusive and exclusive history controls using sparse text, concept and category features. Pure Random, Balanced Exploration, Personalized, Discovery, Subscriptions and Original arXiv have separate behavior. Random-mode training and subscription weighting are optional. [Learning and modes](RECOMMENDER.md) |
| 8. Interest history | Versioned paper snapshots, timestamped feedback, revision edges, reasons, mode and known probabilities support corrections and reproducible fitting. Date filters, per-event exclusions, reversible resets, restoration and permanent per-paper deletion are exposed in Interests. The browser rebuilds the active classifier. [History semantics](RECOMMENDER.md) |
| 9. AI overviews | The optional authenticated bridge tries full HTML, usable PDF extraction and then the original abstract. It labels the analyzed source, bounds the excerpt and verifies short supporting quotations for paper-specific fields. Protected mode restricts result and proof disclosure. [Sources, fields and limits](AI.md) |
| 10. Contextual dictionary | Selecting text in a supported paper or an answer exposes **Explain selection**. Current paper context, follow-ups, simpler and more rigorous explanations, saved glossary entries and explicit understanding status accompany the response. [Dictionary configuration](AI.md) |
| 11–12. Knowledge and independence | **Knowledge** records manually editable levels from Unfamiliar through Advanced for named topics. The AI request can use those topics for explanation. Global and per-paper No Spoilers settings control protected requests. [Knowledge and disclosure](AI.md) |
| 13. Researchers | Paper authors can be followed with a stable identifier when available or a confirmed name-only match. **Authors** includes dates, notes, locally known recent and unread papers and removal controls. [Identity limitations](LIMITATIONS.md) |
| 14. Analytics | **Interests → Analytics** distinguishes observed feedback from model scores. It shows category counts, negative/positive/background responses, observed uncertainty, sample sizes, liked concepts, investigated terms, locally followed papers, reading, knowledge edits and changes over the selected period. [Analytics definitions](RECOMMENDER.md) |
| 15. UI and accessibility | Scoped controls and modal dialogs provide keyboard navigation, focus styles, responsive widths and system/light/dark themes. Native MathML in added views handles supported TeX. Original arXiv removes all added controls. [Rendering](ARCHITECTURE.md) |
| 16. Local architecture | The build bundles local modules with a vendored renderer. Tampermonkey private values hold profiles and cached answers. IndexedDB stores validated public listing metadata. Fitted weights live in memory and extracted paper text stays in the bridge's bounded RAM cache. [Component and storage map](ARCHITECTURE.md) |
| 17. Provider configuration | Pair a local or hosted-model bridge, select an eligible model, review the disclosure and authorize generation. Credentials for a hosted service stay in the bridge process. Request, input/output and estimated cost ceilings are enforced with a persistent daily usage ledger. [Provider setup](AI.md) |
| 18. Data and privacy | JSON backup and import, reading/feedback CSV, bookmark BibTeX, individual feedback and collection deletion, and full local deletion are available. Parsers treat external text as untrusted. The network layer validates destinations and paces arXiv requests. [Data schema](DATA_SCHEMA.md) · [Privacy and security](SECURITY.md) |
| 19. Tests | Unit, bridge and browser fixture suites cover the acceptance areas listed below. [Test commands, automated coverage and environment-dependent checks](TESTING.md) |
| 20. Deliverables | Source, Tampermonkey metadata, the installable bundle, optional Python bridge, fixture, tests, install instructions, design documentation and limitations are in this repository. [Installation](../README.md) · [Known limitations](LIMITATIONS.md) |
| 21. Design principles | Broad category access and Pure Random are always available. Ratings can be revised or deleted. Knowledge, background requests and interest labels have separate records and uses. Optional generation identifies the paper source it analyzed. [Recommendation semantics](RECOMMENDER.md) |

## Acceptance evidence

| Scope | What the repository checks |
| --- | --- |
| Cold start, random selection, empty and overlapping subjects, duplicate prevention | Sampler tests cover cold-start behavior, repeated seeded uniform draws, repeatability, missing categories, maximum coverage and unique paper IDs, including exhaustive small eligibility graphs. |
| Supplied fixture and pagination | The parser regression expects **379 new**, **61 cross-submissions** and **261 replacements**, for **701 distinct papers** on **November 26, 2026**. The input is `fixtures/arxiv-math-new.html.gz`. Its uncompressed digest and byte length are recorded alongside it. Loader cases cover mixed dates, partial counts and failed requests. |
| Feedback, training modes and history | Tests exercise actual fitting from likes and dislikes, neutral and background handling, Random independence, the training switch, exclusion boundaries, revisions, reset, restore and deleting all revisions for a paper. |
| Durable state and data transfer | The store tests cover validation and export/import. A disposable Chromium profile with a userscript-manager adapter exercises saving and reopening. An actual Tampermonkey update requires the installed-copy check. |
| Ambiguous author names | Matching tests distinguish verified identifiers and explicitly confirmed names. The browser suite includes the name-only follow control. |
| Missing HTML, unusable PDF, unavailable provider and grounded answers | The Python bridge and JS client suites exercise fallback, exact evidence checks, disclosure, refused or invalid responses, budget enforcement, local HTTP and cached answers. |
| Math notation and untrusted content | Renderer tests exercise native fraction, radical, subscript, superscript, sum and matrix nodes, preservation of TeX, URL-bearing or unsupported commands, size limits and independent macros. Parser and storage checks validate external text and links. |
| Live environment | Production installation prompts, manager upgrades, authenticated provider accounts, changing paper availability and mathematical interpretation require the respective live environments. See the test guide for the verification actually performed. |
